## 本次踩到的坑（重要，别再犯）

**「自动填值」和「用户手填」抢同一个 v-model，不能只靠 `@input` 事件判断是否被人工改动。**

- 现象：手填个税 20 之后，输入框显示 20，但组件状态里 `componentsDraft.incomeTaxCents` 仍是
  规则值 125.76 —— 保存草稿就把错的金额存进去了（DOM 与状态静默脱钩）。
- 根因：同一个输入事件里 `watch(taxBreakdown, applyComputedTax)`（pre 队列）先跑，
  `Input` 组件抛上来的 `@input` 回调后跑，于是自动填值时 `taxOverridden` 还没置位，
  反手把刚手写的值覆盖回去了。抓到的写入时序：
  `WRITE "520.74" -> 33`（手填）紧跟 `WRITE 33 -> "520.74"`（自动覆盖），两次都是 `overridden=false`。
- 修法：改成**状态判据**而不是事件判据 —— 维护一个 `taxBaseline`（上一次「不是人工改的」值），
  自动填值只在「当前值 === 基准值」时执行，否则把 `taxOverridden` 置位并退出。
  打开弹窗 / 点「按规则重算」「按薪资标准填入」时用 `adoptCurrentTax()` 认下当前值当基准。
  这样与回调顺序无关。同时**删掉了字段上的 `@input="markTaxOverridden(key)"`**：
  置位路径收敛成一处（`taxOverridden` 现在纯由 `applyComputedTax` 的状态判据推出），
  否则「手改后又改回与基准相同的值」会给出两侧数字相同的假提示。
- 顺带记住：`components/ui/input/Input.vue` 用的是 `useVModel(passive: true)`，
  子组件有一份本地副本，父组件写值会同步下来、用户输入要靠 emit 上去；
  一旦 emit 没落到父组件，DOM 会一直显示旧的手填值，**只看输入框看不出来**。
- 验证这类问题**必须同时核对「输入框 DOM 值」和「组件状态」**：
  用 `el.__vueParentComponent` 一路 `inst.parent` 找到持有 `componentsDraft` 的实例读 `setupState`，
  再断言保存草稿的请求体（拦截 draft 路由读 postDataJSON）——只截图是看不出来的。

### 本次踩到的坑 / 教训

- **两级表头会漏识别**：列的 contains 回退匹配原本要求别名长度 ≥ 3，导致「请假 / 病假」两级表头拼出的
  `请假病假` 匹配不到 `病假`，被误判成「数据有问题」。别名回退阈值降到 **≥ 2** 并在注释里写明原因。
  → 教训：表头别名匹配的长度阈值要按最短合法别名定，不能拍一个 3。
- **第二行表头会被当成数据行**：预览多出一行「这一行没有姓名」。加 `isHeaderTail` 判据
  （姓名为空 **且** 所有组件列要么空、要么是字符串文本）来过滤。
- **导入预览表容易被「说明」列撑开**：把多条长警告收成一句 + `title` 里放细节，
  列 `w-72` + `whitespace-normal`，表格 `min-w-[900px]`。
- **同一批文件里同一个人出现两次 → 后端整批 400**，所以前端 `markDuplicates` 先在第 2 次出现处标 `invalid`，
  让用户在预览阶段就看到，而不是提交后吃一个 400。
- 批量发布的 happy path **本机没法实跑**：2026-09 考勤台账是 `open`，
  `publish-batch` 会整批 409「请先完成当月考勤结账，再发布工资条」——这条分支是**预期行为**，不是 bug。

## 用章（印）申请模块：设计定稿，待确认后开工

需求：在「我的申请」下新增「用章申请」，字段对齐线下《用章（印）申请单》
（申请人/用章部门/用章时间/预计归还时间/用章类别/文件名称/份数/事由/备注/经办人/部门主管意见/总经理意见），
并跟踪 5 类章（公章、财务专用章、合同专用章、发票专用章、法人章）的占用状态。

产出：`docs/plans/2026-09-26-seal-application-design.md`（设计文档）+ `tasks/todo.md` 顶部条目。**未写任何代码。**

用户拍板四条（问过才动手，与我的推荐有分歧的是第 4 条）：

| 决策点 | 结论 |
| --- | --- |
| 章的资源模型 | 每类**仅一枚**实体章，占用按类别判定 |
| 时段冲突 | **硬禁止**：重叠即不可选（只能换章或改时段） |
| 通知渠道 | **新建站内通知中心**（消息表 + 顶栏铃铛 + 未读徽标） |
| 逾期未还 | **自动释放占用**（不是我推荐的"占用不释放"） |

关键设计（次日接手先看这几条）：

- **「时段占用」与「实体在借」是两个正交概念**。逾期自动释放占用会产生物理矛盾
  （章还在别人手上、系统显示可用），所以占用判定只看 `status ∈ {pending, approved, checked_out}`
  的 `[useAt, expectedReturnAt)` 区间；另设 `physicalOut`（存在 `checked_out`/`overdue` 未归还）
  作**非阻断**提示，在发章环节提醒「上一枚尚未归还」。
- **区间互斥没法用唯一索引表达**（不同于单人的请假重叠），一期用「提交时校验 + 审批通过时复检」
  两道查询覆盖 TOCTOU 窗口，**不引入租户级互斥锁**；取舍理由写在文档 §3.3。
- **「审批中」也计入占用**，否则会批完才发现撞车。
- 复用考勤的**模式**（两级审批、`user.managerId` 作部门主管、`attendanceRoles.general_manager` 作总经理、
  缺审批人时禁止提交而非自动通过），但**独立建模**（新模型/新路由/独立开关 `sealEnabled`），
  不被考勤开关、工作日历、考勤台账耦合。
- 项目**原本没有任何通知基础设施**（全仓 grep 只命中注释），所以 `Notice` 模型按**通用**命名，
  不叫 `SealNotice`，后续其他模块可复用。
- 图上没有但**必需**的字段：`actualReturnAt`（问题 2、3 的判据来源）、`checkedOutAt`、
  `forcedReturn{by,at,reason}`（管理员强制归还留痕）。纸质单上「经办人」不是申请人填的，
  而是发章时由印章管理员确定。

### 同日补充：印章保管员 + 章使用台账（已并入设计文档「§4 保管员与章使用台账」）

用户追加要求：「用章要有一个专门保管员，记录每个章的使用情况，包括对各种章的归还、结出等使用监督」。
这把模块从「申请工具」升级成「有监督闭环的台账系统」，设计上加了四件事：

- **保管员角色**：租户设置 `sealCustodians = { default, byType: {official, finance, contract, invoice, legal} }`，
  **支持按章类别分别指派**（财务专用章/发票专用章常在财务手上，公章在行政手上），未单独指定回落统一保管员。
  **未配保管员时禁止启用模块**。
  - 关键取舍：**保管员不参与审批**（审批仍是部门主管 → 总经理），只在审批通过后介入 ——
    避免「自己批自己发」。这是把「审批权」和「保管权」分开，不是简单加个角色。
  - 纸质单上的「经办人」= 保管员，**申请人不用填**，发章动作时系统写 `operatorId` 快照。原先设计让申请人填是错的。
- **章使用台账 `SealUsageLog`**：不可变流水，只追加不修改。action 枚举
  `submit / approve / reject / withdraw / checkout / return / force_return / overdue / remind / watch_notified`，
  带 `operatorId` 与 `snapshot`（当时的申请人+部门+文件名称+份数+用章时间+预计归还时间，
  **防申请后续改动影响追溯**）。可 `GET /seal/ledger?sealType&from&to&action` 按章查历史，
  也可在申请详情里渲染该申请轨迹；`GET /seal/statistics` 出每枚章的使用次数 / 累计借出时长 / 逾期次数。
- **监督闭环的三条硬约束**：① 发章、收章、催还、强制归还**只有该章类别的保管员（或 owner 代行）能操作**，
  接口层校验，申请人不能自己把状态推进到「已借出」；② 没经保管员发章的申请不会进入「使用中」，
  从根本上杜绝「没记录就算用了」；③ 归还时若该章后续时段已被他人预约，提示「下一笔 15:00 有人要用」但不阻断。
- **逾期催办链调整**：刚逾期时同时通知**借用人 + 该章保管员**（保管员是日常监督人，应第一时间知晓），
  之后才升级到部门主管 → 总经理。原设计漏了保管员这一环。

`pages/seal/workbench.vue`（保管员工作台：待发章 / 在借 / 逾期三组）、`pages/seal/ledger.vue`（台账页）、
