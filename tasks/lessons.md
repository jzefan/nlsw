# Lessons

- 用户给出考勤页面 500 截图时，应先核对请求 URL、HTTP 状态与后端两个接口的共用调用链，再用未确认工作日历等真实业务状态复现；不能把失败后的空页面误判为“没有数据”，也不能只凭前端构建成功认定页面可用。

- 用户指出新模块控件风格不统一时，要逐页清点原生 `select`、日期/月/日期时间输入以及单选和复选，并优先复用项目已有 shadcn-vue 组件；只有确实缺少的组合控件才补为共享组件，保留原有数据格式、校验和禁用行为。

- 当需求描述是“默认是物流公司的”“保存后下次打开还是修改后的”这类全局业务配置时，先优先按“租户级/公司级共享配置”理解，不要先假设成“当前登录用户专属”。
- 还要继续区分“公司级通用设置”和“某个业务功能内的共享配置”：如果用户说明“每个用户都能改，但别人也能看到”，应优先建模为该功能的共享业务配置，而不是用户偏好。
- 对已有报表页面加小功能时，优先沿用原有版式，只做最小侵入交互；像“抬头可修改”这类需求，先考虑“文字后小图标 + 弹窗编辑”，不要默认新增整块编辑区。
- 做搜索结果或选择列表时，如果用户明确要“像表格一样一行一条”，不要先用卡片式上下两行排版；应优先用带表头的行式布局，再根据空间做截断。
- 做弹窗搜索或空状态时，不要只放一行功能说明文字；优先提供更完整的居中空状态，引导用户知道能搜什么、系统会怎么返回结果，同时先检查弹窗宽度是否足够承载内容。
- 做远程搜索输入框时，不要只满足“能搜”；默认就要加足够明确的防抖，并处理旧请求结果覆盖新输入的问题，避免用户快速输入时产生多次无效请求或结果闪动。
- 做搜索结果表格时，字段以用户明确列出的业务字段为准，不要只展示“够用”的简化列；后端返回结构要一次把这些字段补齐，前端只做排版和格式化。
- 调整弹窗尺寸时不要一把拉到很宽；如果用户只说“再宽一点”，应优先做中等幅度调整，并结合当前场景控制在合理阅读宽度内，而不是直接上超宽桌面尺寸。
- 在固定宽度弹窗里做结果表时，列宽不要继续写死像素；优先用 `fr` 比例列让字段跟随弹窗整体宽度自适应，再配合截断控制信息密度。
- 搜索结果表里不要默认所有字段都 `truncate`；应按字段重要性区分，像提单号、订单号这类关键标识要完整显示，其他说明性字段再允许换行或截断。
- 车船结算页的列表、统计和导出都会各自重建主行与内部运单行；修改状态筛选时必须逐一核对，船主状态不匹配不等于内部运单也应被排除。
- 做搜索结果跳转时，不要让前端再根据展示字段或间接映射去猜目标页面；应尽量由后端返回明确的目标类型或目标路由，避免“看起来像对、实际跳错页面”。
- 如果用户说“打开”“进入”某条业务数据，先确认这是“查看”还是“修改”；不能默认把“打开运单”理解成“进入修改页”，报表查看和编辑入口是两个不同动作。
- 部署脚本的 Node.js 路径必须是目标级配置，并以固定安装目录为准；环境发生迁移后要移除过时的 NVM 假设，不能在远端隐式加载 NVM。
- 部署脚本判断系统服务时必须检查实际运行状态（如 `systemctl is-active`），不能只因为服务单元存在就跳过启动；启动失败应阻止后端重启并给出明确错误。
- 非交互 SSH 中，SSH 登录认证不会自动通过给 `sudo`；涉及服务管理或 Nginx 配置的远端脚本必须显式处理 sudo 认证，并让所有特权调用使用同一机制。
- MongoDB 配置也必须是目标级策略：不能因为默认 systemd 服务正在运行就认定应用数据库可用；部署前需确认该目标实际使用的配置文件与监听端口。
- 当目标服务器已有约定的项目启动脚本时，部署脚本应调用它而不是内嵌等价的进程启动命令；避免绕过该服务器已有的路径、PID 和配置管理约定。
- 公司差异化显示需求必须分别确认每个公司对每个控件/列的可见性；不能把“隐藏车归属下拉”误合并为“车归属和承运单位都隐藏”。
- 排查跨环境登录加密失败时，要先沿“浏览器访问协议 → 前端加密分支 → 后端解密填充”追踪；`localhost` 与 HTTP 公网地址的安全上下文不同，不能先把问题归因于数据库副本或密钥不一致。
- Node.js 全局升级 PM2 不会自动替换内存中的旧 PM2 守护进程；迁移掉 NVM 后，要同步守护进程并重建保存的进程清单。前端这类全局 CLI 必须在 PM2 中记录目标 Node 目录下的绝对可执行路径，且部署后要校验进程已 online，不能只看 `pm2 start` 的命令输出。
- 对需要 `sudo` 的开机服务配置，不能以 `|| true` 静默吞掉失败；应复用非交互部署的认证函数并把目标 Node 的 `PATH` 传给 systemd 生成命令，否则移除 NVM 后重启会失去进程守护。
- 当用户说明目标公司本身采用 standalone 部署时，不要为了进入平台租户管理而切换 SaaS；平台 API 在 standalone 下按设计返回 404。应保留 standalone，用 `ENABLE_ATTENDANCE` 配置本地考勤开关并重启后端验证菜单。
- 新增功能兼容现有账号时，不能把 `mustChangePassword` 缺失误判成必须改密；只有显式标记为 `true` 的新建/重置账号才要求先设置密码，老账号继续用现有凭据，同时保留员工工号、租户关联和薪资角色校验。
- 员工资料中的工号必须是可选业务属性，不能作为账号和租户、考勤或本人薪资记录的关联条件；数据按稳定 `userId` 绑定，展示时才按工号、手机号、部门和姓名逐级消歧。小公司可不维护工号；同名时提供足够上下文识别人员。
- 用户纠正“管理员应有待我审批权限”时，不能只按模块角色隐藏审批入口；要同时核对系统级 admin、公司主账号与考勤角色，并让页面页签和侧栏入口采用一致的授权条件。
- 用户明确要求数字 badge 时，复用项目的 Badge 组件显示数量；不要额外组合红点和数字。
- 页签数量 badge 应用相对定位贴在标签右上角并控制为小尺寸，避免插在标签文字流中改变页签间距。
- 前后端服务的启动与重启由用户手动执行；即使代码变更需要加载，也只说明要启动的服务与命令，不自行终止、启动或重启进程。

- 页面内页签指向左侧菜单已覆盖的兄弟模块时，若用户说明“通过左边菜单导航即可”，应整行删除该页签而不是只去掉链接或保留当前页标签；同时按同组页面（如台账页）的标题+控件版式对齐。
- 筛选区的 label 默认应与控件同一水平行（`flex items-center gap-2`），不要用 `space-y-1` 上下堆叠；外层对齐方式也要随之从 `items-end` 改为 `items-center`，否则删掉页签后控件会贴到徽标行。
- 无登录态验证前端版式：临时在 `front_end/` 放一个 preview HTML + 挂载真实 SFC 的入口（自建 pinia 与 memory router），经 `vite dev` 用 headless Chrome 按目标宽度截图即可看到真实组件版式；接口报错不影响标题与筛选区渲染。
- 本机 headless Chrome 在沙箱内必须加 `--no-sandbox --disable-gpu`（否则 GPU/沙箱初始化失败），截图写出后进程常挂起，需按 `--user-data-dir` 精确清理；不要用 `pkill -f -- "--headless"` 全局清理，会误杀 agent-browser 等其他会话的 Chrome。
- 页面上无条件渲染的跨模块入口，如果目标路由对部分角色会重定向（如 `payroll/statements.vue` 把无工资权限的账号 `replace` 到我的工资条页），用户就会看到两个页签落到同一页；修这类问题时既要去掉无效入口，也要说明目标路由的重定向是按设计保留、且其他入口本身带权限判断。
- 用户要求避免重复申请时，已有记录不能只做日历提示；对应日期也要禁选，并在记录加载完成前阻止选择。
- 日期时间组件的默认小时不能只在选完日期后再填；如果需求是“打开表单默认 8 时/18 时”，空日期状态下的小时下拉也要显示默认值，同时避免向表单提交不完整的时间。
- 调整侧栏菜单顺序时，条件渲染项（待我审批/工资管理/设置）也要落到用户给的位置：能一次把最终顺序写在一个数组字面量里（`...(条件 ? [项] : [])`）就别分散多次 `push`，顺序才可读、可核对。
- 校验菜单这类纯数据函数，可用 esbuild 把 TS 模块打成 ESM（`--alias:lucide-vue-next=桩文件`、`--alias:@=./src`）后在 Node 里按不同角色直接调用，打印实际顺序比对，比只看源码可靠。
- 列表页把「直接可编辑 + 点勾保存」改成「先只读展示、点编辑再进入编辑态」时，只读态要取已保存值（`row` 字段）而不是草稿，否则未保存内容会出现在只读行里；同时要考虑只有一行处于编辑态、脏数据时切换给出提示、以及无改动点确认时如何退出编辑。
- 验证前端交互不必等登录账号：在 preview 入口里给单例 axios 的 `defaults.adapter` 塞桩数据，再用 headless Chrome 的 `--dump-dom` 读出脚本写进 DOM 的断言结果、配合 `--screenshot` 看真实渲染，就能覆盖查看/编辑/保存/拦截等路径；注意 stub 掉接口后页面里 `toast` 需要 `<Toaster>` 才会显示，预览里没有 Toaster 时 toast 断言会为假。
- 行内编辑加上「取消」时，取消必须能还原到编辑前状态：文档型表单用「编辑草稿」而不是直接改原对象，`取消 = 用原数据重建草稿 + 退出编辑态`；对勾在无改动时只退出编辑、不发请求，避免误发空保存。
- 同一页面出现第二处表格时不要照搬第一处的实现细节：员工资料的角色是多选复选框、还有外键（直属经理）要显示成姓名，只读态需要为每个字段单独决定展示内容，而不是简单套用上一页的写法。
- 编辑态的空值不要用 `-`/`无`/`选填` 之类的占位文字冒充内容：用户会把它当成已有值。规则是「空就是空」；只读态才用 `—`/`无` 这类展示约定。
- reka-ui 的 `SelectValue` 在没有选中值时会回显占位符、有选中值时回显选中项文本，所以想让它显示空串必须给 `SelectValue` 传默认插槽自定义内容；同时保留下拉里「无」这一项，用户才清得掉已有选择。
- 用户说「加了 X 才失败」时不要直接照做 X 相关代码：先用真实账号/租户数据把「有 X / 无 X」两条路径都复现一遍（写操作打桩、只读真实数据），确认触发条件再动手；这次附件与报错无关，真正触发条件是请假超过 3 个工作日且租户没有在职总经理。
- 报错文案要给出「触发条件 + 去哪里修」；只说「请配置唯一且有效的总经理审批人」，用户既不知道为什么会触发，也不知道去哪个页面配。
- 在一个已经有红测试的文件里加测试前，先用「还原本次改动再跑一遍」建立基线，避免替别人（或并发会话）的失败背锅；基线失败要如实报告而不是顺手改掉别人的测试。
- 修「遗留失败测试」时先分清是「测试日期/期望值过时」还是「产品行为回退」：用真实工具函数把候选日期跑一遍（工作时段、节假日、调休）再改断言，能避免把真 bug 当成过时测试改掉。
- 内置全国节假日表会把覆盖年份自动并入 configuredYears，凡是断言「未确认日历年」的测试都必须用表外年份（如 2027），否则那条分支永远走不到。
- 前后端各有一份「超过 N 个工作日需总经理终审」的常量时，在前端常量上注明与后端文件一致，并在测试里覆盖阈值两侧，避免两处漂移。
- 同一个页面按子类型拆成多个菜单入口时，优先沿用项目已有的「带查询参数的菜单项」约定（nav-team.vue 的 matchUrl 对含 `?` 的菜单做 fullPath 精确匹配），再让页面从 route.query 读参数下发给列表组件；不要为此新增重复页面文件。
- 拆分入口后要顺手处理三处一致性：列表请求要带过滤参数（服务端过滤，分页才准）、页面标题与空状态要跟着变、新建弹窗要预置并固定该类型，否则用户会在「请假申请」页新建出加班申请、然后看不到它。
- 同一组件被多个视图复用（我的申请/待我审批/审核记录）时，页内页签要按视图收敛：入口已进左侧菜单的视图不要再重复显示页签，只在同属一个业务域的子视图之间保留切换；改动后要用「有权限的账号」把每个视图都跑一遍，避免权限分支下面的页签漏掉。
- 「某类账号不应出现在业务列表」这类需求要连历史一起想：列表、统计、以及**已结账月份的快照**都要过滤，否则旧数据里那行还在；快照过滤注意别把「停用但历史有过记录」的员工一起丢掉，所以按范围（纳入统计的本租户员工）过滤而不是按状态过滤。
- 新增「是否纳入某统计」的开关时，老数据没有字段要按「纳入」处理（查询 `$ne: false`、前端 `!== false`），并顺手在写入接口上做同样的守卫，否则被排除的人仍能被人工写进台账。
- 列表里出现「姓名（工号）」这类后缀时，先找是谁拼的：本项目统一由 `utils/person-label.js` 负责消歧，只在「需要从一批人里挑一个」的场景（下拉、候选人）才该用；台账这种同一行已经展示工号/手机号的表格不该再用，删除调用并顺手清洗历史快照里已存下的字段。
- 去掉某个展示字段前先查历史数据是否已经落库（如结账快照会保存计算好的 displayName），只在写入侧改会留下旧值，必须在读取侧统一清洗。
- 「未设置 = 停用」这类语义要全项目对齐一个判据：本项目登录（passport）用的是 `status === 'disabled'`，而考勤/薪资里散落着 `status !== 'active'`，历史账号（字段缺失）就在后者被误判。改之前先找权威判据，再逐个替换，并把查询条件同样改成 `$ne: 'disabled'`，否则会出现「列表显示在职但系统查不到这个人」的错配。
- 用户说某个字段「和当前功能没关系、不要强制关联」时，要把它在**整条链路上的拦截点**都找出来（授予/交接/查看/锁/操作者判断都要查），只在按钮上放开会出现「按钮能点但接口 409」；同时保留字段本身，避免影响它原本负责的其它流程。
- 用脚本按「起始下标 + 结束下标」删除代码块前，必须先断言 start < end；本次两个 index() 取反了顺序，`s[:start] + s[end:]` 把中间的函数整段复制了一份、随后的第二次删除又吃掉了后面的代码，属于不可逆破坏（这些文件还没进版本库）。改动大文件要用 edit 工具逐处替换，并在每次结构改动后立刻跑类型检查。
- 误删源码后的补救顺序：先按报错列出缺失标识符，再到上一次成功构建的 `dist/assets/*.js` 里按特征字符串（如 toast 文案）定位压缩后的实现还原，最后用真实页面预览把每个受影响页签都点一遍确认行为一致。
- 「某身份由谁决定」这类改造要一次性把写入口收敛到一个地方：职位=总经理后，员工资料的角色勾选框、薪资权限的「设为总经理」都必须撤掉，否则两处写入会互相覆盖；同时把唯一性标记（租户唯一索引）的迁移放进同一条同步逻辑里，换人时先收回再写入。
- 用户看到「已经改过的旧文案」时，先分清是源码残留还是**运行中的旧进程/旧构建产物**：`grep` 源码确认文案是否还在，再确认前端是 vite dev（HMR 立即生效）、后端是 `node app.js`（无热加载，必须重启）。本次旧提示只存在于 front_end/.build-check 的旧构建产物里，源码早已改掉，用户看到的 toast 来自未重启的 1080 进程。
- 改完权限/文案后，用真实控制器把「主账号/管理员/总经理/普通员工」四种操作者的返回都跑一遍打印出来，这样重启前就能确认重启后会得到什么结果，比只说「重启就好」有说服力。
- 「我改的代码没生效」这类反复出现的困惑，值得做成产品能力而不是每次口头解释：本次让后端自己记录启动时的源码时间戳并提供公开的 `/server-version`，前端在外壳上提示「重启后端才生效」。判据只覆盖后端源码目录，前端改动不会误报；接口不存在（老后端）时要静默忽略，否则会在重启前先报一次错。
- 同一页面的多个表格要保持同一套交互范式：加完「查看-编辑-确定」后，页内其它列表（薪资权限）也要照搬同一套状态与守卫（单行编辑、脏数据拦截、取消还原、无改动只退出），否则用户会看到两种风格混在一起。
- 用户给一张表头截图要求「严格按图展示」时，先把「字段集合 / 名称 / 顺序 / 分组」四件事逐项对齐（含两级表头），并把列定义抽成一份共享常量，让录入表单、工资条、统计口径都引用它；否则同一概念在不同页面会出现「餐补/午餐补贴」「综合工资/工资总额」这种漂移。
- 删除一个模型字段前先查库里的实际使用量（本次工资条数据为 0，删除安全零风险），并把「模型 / 计算键 / 前端类型 / 字段列表 / 测试断言」一起改到位，避免只删一处导致类型或合计对不上。
- 侧栏「分组怎么分、叫什么名字」是产品决定，不要从信息架构自行推论：给方案时要把「拆成两个一级分组」与「单分组内排序」两种代价一起摆出来让用户拍板。本次用户明确否掉拆组，改为单分组更名「考勤管理 → 考勤与工资」，薪资类入口维持在同一分组的考勤类之后。
- 判断两个入口该合并成页签还是并列成菜单，看「是不是同一个业务对象的不同投影」：台账/统计同源同权限（明细 vs 汇总、单月 vs 跨月）→ 合并为「明细台账 / 统计汇总」页签；员工侧汇总并进我的工资条、财务侧汇总并进工资管理，都属于「汇总视图挂到宿主入口」，合并的是入口而不是页面内容。
- 删掉一个入口前要确认它承载的信息在宿主页面已被承接（本次把逐月 收入合计/工资总额/请假与旷工 三列补进我的工资条年度表），否则就是静默丢功能。
- 合并掉独立入口时必须保留旧地址的重定向并按权限分流（`/attendance/payroll/statistics` → 有全公司薪资权转 `statements?tab=statistics`、普通员工转 `my`），并把目标页的页签做成可被查询参数定位（`?view=` / `?tab=`），否则历史书签和通知链接会落到空白页或无权限页。
- 「程序自动填值」与「用户手填」共用同一个 v-model 时，别只用 `@input` 事件判断「用户改过没有」：同一个输入事件里 pre 队列的 `watch` 先跑、组件抛上来的 `@input` 回调后跑，自动填值会在标志位还没置位时把刚手写的值覆盖掉，表现为**输入框显示手填值、组件状态里却是旧值**，保存时存错数据。改用状态判据（维护「上次自动写入的基准值」，只在当前值仍等于基准值时自动覆盖；打开/重算时把当前值认成基准），与回调顺序无关。
- 验证「界面显示」与「实际提交」是否一致时，必须两条腿走路：截图/DOM 读值只能证明看得到什么，还要读组件内部状态（`el.__vueParentComponent` 逐级 `inst.parent` 找持有状态的实例读 `setupState`）并拦截请求体（`page.route` + `postDataJSON`）断言真正提交了什么。本项目 `components/ui/input/Input.vue` 用 `useVModel(passive: true)`，子组件有本地副本，DOM 与父组件状态脱钩时看不出来。
- 验证强度必须按「改动影响面」分级，不要按仪式感一刀切：文案/样式/图标这类界面微调只要求能编译并开页面扫一眼，**不跑测试套件、不补测试、不建 todo**；单页逻辑跑相关文件类型检查 + 该模块已有测试；只有接口/模型/权限/共享 store 这类跨模块改动才走模块测试 + 主流程，部署迁移等不可逆操作才要全量 + 备份 + 回滚。判不准取低档并说明依据，只有用户明确要求才跑全量。同时「不测 ≠ 不报」：跑了什么、没跑什么要如实说。
- 配置类文档（`AGENTS.md` 等）里不要写「验证为王 / 测试驱动 / Never mark a task complete without proving it works」这类绝对化措辞——绝对表述会把小改动也拖进重流程；要写成带判据的分级规则，并明确「什么情况下不必做」。
- 入口形态来回改（合并成页签 ↔ 拆成菜单项）时，**两个方向都要保留旧地址**，且必须同时处理「反向那一侧的旧跳转壳」：把工资管理的三个页签拆回独立页面时，`statements.vue` 要把 `?tab=statistics|settings` 转到新页面，而 `statistics.vue` 原来那个「跳回 `statements?tab=statistics`」的壳必须一起删掉，否则两边互跳成死循环。改完用真实浏览器把旧地址走一遍（`?tab=` 两种取值）确认落到正确页面。
- 改侧边栏结构后要断言三件事，别只看截图：① 子项顺序与文本（`[data-sidebar="menu-sub-button"]`）；② 当前路由对应的子项高亮（该元素的 `data-active` 属性）；③ 被移除的旧控件真的不在了（本次断言工资表页 `nav button` 为空数组，证明三个页签按钮已删干净）。
- 导入类的“表头别名匹配”里，**contains 回退的长度阈值要按最短的合法别名来定，不要随手写 3**：两级表头拼出来的列名（如“请假/病假”→“请假病假”）会因此匹配不到“病假”，被误判成“数据有问题”。本次是把阈值从 ≥3 降到 ≥2 并加注释说明原因才修好。
- Excel 解析要防“第二行表头被当成数据行”：识别出表头行后，用显式判据（姓名为空 **且** 所有数据列要么空、要么是文本）过滤紧随其后的“表头尾行”，否则预览会多出一行“这一行没有姓名”。
- 导入预览表里加“说明/备注”列时，列宽不要放任长文案撑开整张表：把多条警告收成一句 + 细节放进 `title`，列宽给固定上限（`w-72`）+ `whitespace-normal`，表格设 `min-w-*` 兜底。
- 批量接口遇到“同一人重复出现”是整批拒绝的，所以**前端要在预览阶段先标重**（第 2 次出现即标非法），让用户在这里看到，而不是提交后吃一个 400——错误要暴露在最靠近用户决策的位置。
- 一次批量操作里，“取月锁 / 查台账是否结账”这类前置校验只做一次（整批共用），不要放进逐人循环里；单条发布仍走同一段校验逻辑，靠一个 `requireClosedLedger` 参数区分，避免单条与批量两套代码漂移。测试里可以直接断言事件顺序（`['lock:2026-09','check-closed','release:2026-09']`）来固化“只取一次锁”。
- 批量写入类接口**不要接收前端算好的汇总值**（合计/实发/单位合计），只收录入项、服务端统一重算——否则同一份工资会因来源不同（手录 vs 导入）出现两个口径。
- 判定“全量测试失败是否由我引起”要看文件与领域：本次 122 条里唯一的失败在 `test/vessel-settle-weight-range.test.js`（航运结算浮点断言），与工资模块无关，属既有问题——如实报告“1 条失败但与本次无关，未动”，不要顺手改别人的测试，也不要含糊说成“测试全过”。另外 `node --test test/` 在本机 Node 22 会把目录当模块解析而报 `MODULE_NOT_FOUND`，要用 glob：`node --test test/*.test.js`。
- 让“程序生成的模板/文件”与用户手上的真实文件对齐时，判据要用**结构比对**（逐格值 + 合并区域），并且**至少用两个不同的库各比一次**（本次生成用 JS `xlsx`、复核用 Python `openpyxl`）——同一个库读写会按自己的理解“自证一致”，看不出真实差异。反过来，能自动生成就把它当可断言产物验，别只靠肉眼截图。
- Excel 里“只有首行有列名”的列在真实文件中是**纵向合并**的，读成二维数组后第二行为空——所以「首行 + 次行拼合」的列名匹配逻辑天然吃得下，**不要为纵向合并写特例**；要防的是另一头：表头行探测不能只按“匹配到的列名个数”打分，否则只含子列名的那一行可能反超。
- 手动写死合并坐标（`{s:{r:0,c:7},e:{r:0,c:9}}`）在表头一变就失效，要改成**从两行表头推导**：首行有名字且次行为空 → 纵向合并；首行有名字且后面跟到下一个有名字的列 → 首行横向合并。以后加列/改分组不用再改下标。
- 多段浏览器验证脚本里，上一段打开的模态弹窗不关会把背景 inert 掉，下一段的按钮点击直接超时（表现为“按钮明明在却点不到”）。跨段操作前按**正常路径**点关闭并等 `hidden`，不要用 force click 绕。顺带：去掉模板里的「序号」列后，预览里的「行号」仍应按 Excel 实际行号算（`index + 1`），不要误改成从序号列取。
