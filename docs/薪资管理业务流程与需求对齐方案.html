薪资管理业务流程与需求对齐方案

系统现状综述、业务全景流程图与核心决策确认清单
编制日期：2026年9月

本文档系统梳理企业薪资管理模块的现行设计、已实现的端到端业务闭环，并汇总明日与需求各方（业务主管、人事、财务、总经理）协同研讨的关键决策议题。系统立足于小微企业日常管薪特点，遵循“标准底稿沉淀、自动辅助推算、财务精细把关、员工自主查阅”的原则，构建兼顾规范性与操作灵活性的薪资管理体系。

一、 当前已实现的薪资业务闭环流程

薪资模块涵盖自考勤数据归档、固定薪资标准调用、当月变动数据核算、个人所得税推算，直至批量发布与员工自主查阅的全链条闭环。整体流转如下流程图所示：

1. 薪资标准与考勤联动
支持对每位员工预先设定基础薪资标准（基本工资、岗位工资、工龄工资、满勤奖）及社保公积金缴纳基数与比例。每月生成工资表时，若当月尚未录入，系统会自动根据标准生成预估底稿，同时调取考勤月结数据中的请假、旷工时数供核对。
2. 灵活填报与智能纠偏
财务人员可在系统界面直接逐人填报、逐项微调，亦可通过固定样式的通用电子表格批量导入。系统支持两级复合表头自适应识别，录入项严格校验金额范围，计算列（工资总额、合计应发、实发金额等）均由系统统一定义计算，杜绝口径偏差。
3. 个人所得税累计预扣预缴
内置国家税务主管机关现行的居民个人工资薪金累计预扣预缴算法。系统自动归集该员工当年历史月份的已发收入、专项扣除及已缴税额，智能推算本月应扣个税。财务可查阅完整的推算明细，若有特殊情况允许手动改写并锁定防覆盖。
4. 发布管控与纠错撤回
为确保薪资严谨性，系统设定“当月考勤未结账严禁发布工资条”的前置强规则。发布支持单人核准与全员批量发布。若发布后发现个别员工数据有误，财务可执行“撤回”并登记原因，撤回后员工端即时不可见，修改后重发将递增版本。

二、 薪资结构与计算规则

系统现行数据模型采用“十六项细分录入项目 + 六项系统核算总额”的设计，严格按整数“分”进行精确运算与存储，杜绝尾数浮点偏差。

类别分组 包含明细项目 生成与填报方式
收入项目 基本工资、绩效工资、岗位工资、工龄工资、满勤奖、交通补贴、午餐补贴、加班补贴 基本、岗位、工龄、满勤可由薪资标准预设自动带出；绩效与各项补贴由财务每月填报或表格导入。
单位承担 社会保险单位承担、住房公积金单位承担 系统按人员设定的单位缴纳基数乘以缴纳比例自动计算，四舍五入精确到分；亦可手工微调。
考勤扣款 病假扣款、事假扣款、旷工扣款 界面展示该员工当月考勤缺勤时长，具体扣款金额目前由财务人员根据制度线下核准后录入。
个人代扣 社会保险个人承担、住房公积金个人承担、个人所得税扣款 社保公积金按个人基数与比例自动计算；个税由系统根据本年度累计税法公式自动推算，支持手调。
系统统一核算公式：
1. 收入合计 = 基本工资 + 绩效工资 + 岗位工资 + 工龄工资 + 满勤奖 + 交通补贴 + 午餐补贴 + 加班补贴
2. 工资总额（含单位社保公积金） = 收入合计 + 单位社会保险 + 单位住房公积金
3. 合计应发（不含单位承担） = 收入合计 − (病假扣款 + 事假扣款 + 旷工扣款)
4. 实发金额 = 合计应发 − 个人社会保险 − 个人住房公积金 − 个人所得税扣款

三、 权限划分与查看规则

薪资模块按照岗位分工合理划分各角色的查看与操作边界，保障流程各司其职：

角色身份 薪资管理权限 范围与查看说明
财务专员 全员薪资编制、修改、导入、发布、撤回、薪资标准维护 需由企业主账号在人员管理中分配财务角色，方可进入薪资管理模块进行日常编制与发布。
总经理 / 董事长 全员月度工资表、薪资统计报表、薪资标准只读查阅 具备全公司工资数据汇总与明细查阅权，不参与日常录入与发布，保障数据查阅与审核独立。
普通在职员工 仅可查阅本人已发布的月度工资条及本人年度汇总 员工登录系统后仅展示绑定本人账号且已正式发布的工资单记录；草稿状态及他人工资不可见。
系统超级管理员 默认不分配全员工资查看权 管理员主要负责基础系统配置与账号管理，若未兼任财务或管理职务，不显示薪资明细数据。
权限与操作留痕说明
系统遵循“权责分明、留痕可溯”原则。所有工资条的保存、发布、撤回均自动记录操作人账号与操作时间；已发布的工资条若需更正，旧版本保留归档形成历史版本链，撤回必须登记原因，做到每笔改动皆有据可查。

四、 明日与需求方核心对齐清单（重点研讨议题）

结合业务实际落地需求与制度细则，建议在明日会议中重点与需求方确认以下五个关键议题：

议题一：考勤扣款与加班补贴的核算模式（手工录入与自动折算的比对）
重点确认项
系统现状：工资表展开行会自动提取该员工当月的考勤台账数据（如事假、病假、旷工时数及加班工时）供财务核对，但具体扣款与补贴金额目前由财务在线下计算完毕后手工录入或通过表格导入。
请需求方决策以下问题：
  • 扣款自动化期望：后续是否需要系统根据审批通过的缺勤时数自动计算扣款金额，还是维持现状由财务核准后手填？
  • 计薪基数口径：若需系统自动计算扣款，日工资计算基数按什么标准核定？（是以“基本工资”为基数，还是以“全额应发工资”为基数？月计薪天数是按国家法定的二十一点七五天，还是按当月实际排班工作日折算？）
  • 病假与加班系数：病假扣款是否需结合员工司龄按比例发放（如发给百分之六十或八十）？加班补贴是按固定标准包干填报，还是需严格按工作日一点五倍、休息日两倍、法定节假日三倍自动折算？
议题二：个人所得税专项附加扣除与社保公积金核定
税务与核算
系统现状：系统已实现标准的年度累计预扣预缴算法，但由于目前未录入员工七项专项附加扣除（如子女教育、房贷利息、住房租金、赡养老人等），系统推算个税时该项暂按零计算；系统支持财务手工改写实际税额并锁定防覆盖。
请需求方决策以下问题：
  • 专项扣除采集方式：财务日常计算税金时，是否习惯从自然人电子税务局系统直接导出各员工的实扣税额，再直接手工录入或通过表格导入本系统？
  • 个税功能定位：目前系统支持“系统推算预估 + 财务手动微调并锁定”，该模式是否已能满足现阶段财务算税习惯？后续是否需要支持导入税务局导出的专项扣除表格？
  • 社保公积金定级：系统目前支持为员工单人或批量设定社保公积金基数和比例，是否满足每年年度社保基数调整的维护要求？
议题三：业务审批流与考勤闭环协同
流程与规则
系统现状：当前流程为“财务录入草稿 → 财务直接发布生效”，发布前系统硬性校验当月考勤台账必须处于“已结账”状态；流程中未设置额外审批节点。
请需求方决策以下问题：
  • 审批节点设置：在财务发布工资条面向全员公示前，是否需要在系统内增加审批环节？（例如：财务制表 → 部门主管/总经理线上审批 → 审批通过后自动对员工公开）。
  • 发薪日应急处理：若逢约定发薪日，但个别部门考勤审批存在延误导致考勤台账未结账，系统是否应允许财务在特批授权下“先行发放工资条”，还是必须严格坚持“考勤结账后方可算薪发薪”的原则？
  • 考勤重开防脱节：若考勤管理员在月结后因特殊原因“重新开启”并修改了考勤数据，对于该月已发布的工资条，系统应采取哪种策略？（推荐：若当月已发布工资条，先限制重开考勤；如确需调整，需先撤回工资条）。

议题四：实付发薪登记与资金流水管理功能
功能解禁确认
系统现状：系统底层数据模型已完整实现了实际发款批次登记、分批付款、退款记录、实际发薪日期、银行转账凭证附件存储及防超额校验功能；此前为突出工资条核算，前端界面暂将资金流水模块关闭隐藏。
请需求方决策以下问题：
  • 发薪记录需求：企业是否需要在本系统内登记“某年某月某日实际通过网银向某员工打款多少元，并上传银行回单凭证”？
  • 管理边界界定：还是本系统定位为“薪酬核定与电子工资条发放工具”，具体的打款支付与资金流水完全在线下网银处理，无需在系统内逐笔登记付款凭证？（若确认需要，系统可随时解禁展示该模块）。
议题五：电子表格导入与人员识别机制（无工号场景适配）
人员匹配规则
已明确规则：由于企业规模相对精简，内部日常不推行和维护统一员工工号。系统导入与考勤关联当前已全面优化为“以员工真实姓名作为核心匹配依据”。
请需求方决策以下问题：
  • 同名同姓辅助规则：当企业内部出现同名同姓人员时，系统要求在表格导入时补填手机号进行唯一性消歧；请确认各部门人事档案中的员工手机号是否已做到全员准确完备。
  • 模板样式核对：明天会议建议现场索取一份财务正在实际使用的电子表格空白样张，与系统内置的导入模板进行列名与顺序逐项核对，确保现有表格能够免修改直接导入。
  • 离职员工查阅权限：员工离职并在系统中停用账号后，目前默认无法登录查看其在职期间的历史工资条。从人事管理与员工关怀角度，是否需要为离职人员提供专用的受限查阅通道？

五、 特殊边界场景应对与规则建议

1. 考勤重开与工资条联动脱节防范
场景：行政在考勤结账后重新开启修改，若当月已发布工资条，容易出现考勤变动而工资条未同步更正的账实不符。
建议：系统增加互斥控制——当月若存在已发布工资条，暂不开放直接修改已结账考勤台账；必须由财务先撤回该月工资条，方允许修改考勤，形成连贯闭环。
2. 离职停用员工历史查阅便民保障
场景：员工离职后账号停用，无法查阅过往工资条，若发生收入核对需求需由财务人工翻找历史凭证。
建议：对停用账号做精细化控制——仅阻断其业务操作与新数据查看，保留独立的“仅查阅本人在职历史工资条”受限入口，既安全又便于员工自查。
3. 差错修改与版本留痕机制
机制：工资发布后若发现个别人员补贴录入错误，财务执行撤回后员工端即时不可见，修改后重新发布自动递增版次，系统保留原版本快照与撤回原因，确保每笔修改都有迹可循。
4. 算税公式透明度与财务自主权
机制：系统个税推算提供透明的累计收入与减除费用明细看板；遇到跨年调薪或税局核定差异，财务可直接手填税额并锁定，兼顾了算法便捷性与财务自主裁量权。
