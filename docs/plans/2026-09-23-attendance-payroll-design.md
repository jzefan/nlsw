# 考勤与工资条需求设计

日期：2026-09-23。状态：持续实现中；用户已确认采用建议薪资公式及北京时间自然月。模块开关、员工关系、日历、申请与审批已实现；月台账及薪资模块正在开发。

目标：为军铁增加可开关的「考勤管理」，覆盖申请、审批、月度考勤、工资条和统计，复用现有登录账号和公司隔离。

本文将用户明确要求列为必须实现；未明确的制度规则均为建议。三张线下表仅作为字段和流程参考，其中的附件要求、签字和备案不自动视为新增强制审批要求。

## 1. 范围与系统现状

一期建议形成闭环：员工申请 → 上级审批 → 行政确认月度考勤 → 财务填写并发布工资条 → 登记实际发薪 → 月度、年度统计。

建议一期采用「审批记录 + 行政确认」作为考勤来源。打卡、定位、人脸识别、复杂排班、自动计税及银行代发暂列后续；是否一期加入上下班打卡待确认。没有申请记录不代表正常出勤，更不能直接判定旷工。

已核对现有代码：

| 现有设计 | 本次处理 |
| --- | --- |
| 账号身份为平台、公司主账号、成员；另有职务及业务权限 | 保留既有设计，增加考勤相关配置 |
| 职务选项有董事长、经理、业务员、会计、统计员；没有总经理专用身份 | 明确指定总经理账号，不能根据「经理」「董事长」或主账号自动推断 |
| 用户无部门、直属上级、独立工号；`no` 为顺序号 | 补充可选员工资料，继续使用原账号登录 |
| `SaleDep` 是销售部门字典，无员工组织关联 | 新增轻量组织部门，不直接混用物流业务字典 |
| 已有后端功能配置、登录信息中的 `features`、动态侧栏 | 沿用链路增加考勤开关 |
| `admin` 在通用权限判断中拥有全部权限 | 薪资使用独立授权，普通管理员不可自动查看全员工资 |

代码依据：`models/User.js`、`models/SaleDep.js`、`models/Tenant.js`、`utils/permissions.js`、`utils/tenant.js`、`controllers/api/user.js`、`front_end/src/pages/admin/users.vue`、`front_end/src/services/api/user.api.ts`、`front_end/src/components/app-sidebar/data/sidebar-data.ts`。

## 2. 开关与菜单

| 场景 | 建议规则 |
| --- | --- |
| SaaS | 租户配置 `settings.attendanceEnabled`，默认关闭；本次仅为军铁租户开启，由平台配置 |
| 独立部署 | 部署参数 `ENABLE_ATTENDANCE=true/false`，默认关闭；部署时显式选择，重新部署保留已有选择 |
| 生效规则 | SaaS 读取租户设置；独立部署读取部署参数，两个来源按部署模式择一，避免冲突 |
| 前后端 | 后端统一返回 `features.attendance`；开关关闭时隐藏菜单、阻止直接访问页面及接口 |
| 关闭后 | 保留全部历史数据，停止模块访问和业务操作；重新开启恢复，不删除或重置记录 |

不根据公司名称是否包含「军铁」决定权限，避免改名或独立部署后失效。开关只控制模块是否可用，不授予薪资访问权；关闭前提示未处理审批和未完成发薪事项。

左侧新增「考勤管理」，按权限展示以下入口：

| 菜单 | 内容 | 可见人员 |
| --- | --- | --- |
| 我的申请 | 请假、加班、外勤三个标签；申请进度、历史记录、假期余额 | 已关联员工的账号 |
| 待我审批 | 待办、已处理；申请详情及意见 | 对应审批人 |
| 考勤台账 | 按月、部门、员工查询；实际情况确认与月结 | 行政、总经理；经理仅管理范围；员工本人只读 |
| 我的工资条 | 已发布的本人月度工资及年度汇总 | 已关联员工的账号 |
| 工资管理 | 按月录入/导入、发布、发薪登记及工资统计 | 财务、总经理；总经理默认只读 |
| 统计报表 | 考勤月报、年报；薪资报表单独授权 | 随对应数据范围开放 |
| 考勤设置 | 部门、上级、日历、工作时段、假期规则 | 被指定的考勤管理员；敏感薪资授权单独管理 |

## 3. 用户与权限

员工补充：工号（选填；填写时公司内唯一）、部门、岗位（复用现有职务展示）、直属经理、入职/离职日期、是否纳入考勤。员工与申请、台账、工资记录按稳定账号 ID 关联并校验租户，不依赖工号；人员展示按工号、手机号、部门、姓名逐级消歧，同名时补充登录名。离职停用并保留历史，不删除已有关联记录的员工。

| 业务身份 | 申请/审批与考勤范围 | 工资权限 |
| --- | --- | --- |
| 普通员工 | 提交本人申请，查看本人记录 | 仅本人已发布工资条 |
| 上级经理 | 审批分配给自己的单据，查看所负责员工的考勤 | 仅本人已发布工资条 |
| 总经理 | 超过3天请假终审；全公司考勤只读 | 全公司工资与薪资统计只读 |
| 财务（薪资负责人） | 查看核薪所需的已确认考勤汇总 | 全公司工资录入、导入、发布、发薪登记、导出 |
| 行政/考勤管理员 | 维护日历与组织、全公司考勤确认、备案、考勤报表 | 仅本人已发布工资条 |
| 系统管理员/公司主账号 | 维持原账号管理权限；考勤管理需另外指定 | 无全员工资权，员工身份下仅本人 |
| 平台运维 | SaaS 功能开通 | 无租户工资读取权 |

身份可兼任，权限取明确授权的并集。现有「会计」可以作为选择薪资负责人的候选，不能直接让所有会计、所有经理或管理员默认获得薪资权限。

必须守住的边界：

- 工资列表、详情、导出、统计、附件均在服务端校验公司和员工范围；普通员工无法通过修改参数访问他人工资。行政考勤报表不含工资金额，经理也看不到部门工资合计。
- 薪资财务和总经理身份不纳入原通用用户编辑接口；首次启用明确登记总经理及薪资负责人，后续由总经理维护薪资负责人并留痕，总经理变更走受控交接，普通管理员不能给自己提权。
- 历史存量账号若没有显式的改密标记，继续使用原密码，不因启用考勤或薪资功能而强制改密；只有明确标记为需要改密的新建/重置账号，完成密码设置后才能使用薪资角色。密码重置应撤销旧会话；用于身份恢复的手机号等凭据变更，需旧凭据本人验证或受控人工恢复并审计，原用户编辑接口不得绕过，防止先改手机号再冒用员工身份。
- 审批人只能操作当前分配给自己的待办；不能审批本人申请。经理本人的申请交总经理；总经理本人的申请交预先指定的其他审批人，该审批授权不附带薪资权限。

## 4. 请假规则与流程

表单保留：姓名、部门、岗位、工号（自动带出）；请假类型、开始/结束日期时间、有效小时数、折算天数、事由、附件、备注。审批人、意见和时间自动记录，替代纸面签字。

假种参考线下表：事假、病假、年假、婚假、产假、陪产假、丧假、育儿假、其他；增加调休假以承接加班调休。病假诊断证明、年假工龄证明可配置为必填，具体由军铁确认。

时间计算建议：

- 最小申请单位为1小时，按公司工作时段计算有效时长并扣除午休；界面同时显示「小时」及「天+小时」，审批和统计以小时为准。
- 公司日历包含工作日、休息日、法定节假日、补班日。提供年度节假日预置/导入，由行政核对发布，并可将指定日期改为假日或工作日；具体日期设置优先于每周默认规则。未配置年度日历时明确提示，不能假设法定节假日等于周末。
- 请假的休息日、节假日默认禁选；允许区间跨过这些日期，区间中的非工作时段自动扣除并展示明细。补班日可请假；全区间有效时长为0时不能提交。加班申请允许选择节假日。
- 「超过3天」建议按工作小时折算，若每天8小时，则超过24小时才加总经理审批，正好24小时无需加审。8小时是待确认的制度参数。
- 跨月/跨年请假按每天的有效小时拆分统计；提交时保存日历规则和计算结果，后续日历调整不静默改写已审批单据。
- 年假、调休假建议保留简单余额台账：行政录入初始额度，申请时占用，批准后扣减，驳回/撤回释放，已生效撤销批准后返还；所有调整留痕，避免重复扣减。

审批流程：

```text
员工提交 → 直属经理审批 ── 不超过3天 → 通过 → 行政备案
                     └─ 超过3天   → 总经理审批 → 通过 → 行政备案
```

行政备案默认是自动归档及可查看，不增加人工审批节点。缺少审批人时禁止提交并提示补全配置，不自动通过；同一人兼任直属经理与总经理时合并重复节点并记录原因。

通用状态：草稿 → 审批中 → 已通过 / 已驳回 / 已撤回。驳回需意见；审批中修改需撤回重提；已通过记录不可直接编辑，走撤销/变更申请并重新审批。人员离职导致待办失效时由考勤管理员转交合格审批人并记录原因。

待审批和已生效的重叠请假须拦截；与外勤、加班的冲突按实际时间段提示并处理，不重复计时。待办及审批结果在系统内提醒，支持打印为原线下表单样式。

## 5. 加班与外勤

统一申请入口，按类型展示差异字段，均由直属经理审批后自动备案。

| 类型 | 字段与处理 |
| --- | --- |
| 公共字段 | 姓名、部门、开始/结束时间、时长、地点、事由、工作内容、附件、备注 |
| 外勤 | 增加对接对象；在工作时段内外出办事，作为正常履职记录，不自动计为加班 |
| 加班 | 增加补偿方式「申请调休/申请加班费」，记录工作日/休息日/节假日分类；通常计算正常工作时段之外的有效时长 |

申请批准代表允许安排，不直接证明实际完成。建议行政月结时根据实际执行情况确认外勤、加班时数，并保留批准时数与确认时数差异及原因。

确认的加班时数按最终补偿方式分别入调休台账或提供给财务核薪；同一时段不能同时兑现调休和加班费。调休折算、有效期及不同日期类别允许的补偿方式由公司配置确认，系统不预设所有节假日均可调休。外勤期间确有额外加班的，另建关联加班单，仅核算额外时段。

## 6. 工资条与发薪

每人每个工资月份一份有效工资条，财务手工填写，也支持固定 Excel 模板导入。以稳定账号 ID 匹配员工；录入/导入选择员工时，工号优先作为显示和查找线索，缺失时按手机号、部门、姓名消歧。重复姓名必须展示足够上下文供财务确认，不按姓名猜测或静默覆盖。

按截图保留字段并分组：

| 分组 | 内容 |
| --- | --- |
| 基本资料 | 工资月份、员工、工号、部门 |
| 工资与奖金 | 基本工资、绩效工资、岗位工资、工龄工资、满勤奖 |
| 补贴 | 交通补贴、午餐补贴、加班补贴 |
| 公司承担 | 社保公司承担、公积金公司承担 |
| 个人承担 | 社保个人承担、公积金个人承担 |
| 考勤扣款 | 病假、事假、旷工扣款；对应时数在考勤摘要中展示，避免金额与时数混淆 |
| 合计 | 工资总额（含社保公积金）、合计应发（不含）、个人所得税扣款、实发金额 |

截图中两列合计的口径存在歧义。用户已确认先按以下建议公式实现；金额由财务录入，系统以整数分计算：

```text
收入小计 = 各项工资 + 奖金 + 补贴
工资总额（含公司社保公积金） = 收入小计 + 公司社保 + 公司公积金
合计应发（不含公司承担） = 收入小计 − 考勤扣款
实发金额 = 合计应发 − 个人社保 − 个人公积金 − 个税 − 安全金
```

公司承担部分不作为员工现金收入再次发放。个税、社保、考勤扣款与安全金由财务填写；系统只做已确认公式的算术计算与校验，金额精确到分，不根据请假天数自动推定扣款或税率。

发布流程：财务录入/导入 → 校验和预览 → 发布 → 员工查看。总经理可查看全员资料；默认不强制加入发薪前审批，以保持流程简单。

分别记录三类状态：

- 工资条：草稿 / 已发布 / 已撤回。员工只看已发布版本；更正需撤回并生成修订记录，重新发布通知员工，保留旧版审计记录。
- 工资支付：未发放 / 部分发放 / 已发放。财务登记实付日期、金额、凭证及备注；多次支付累计，不能用「工资条发布」代替「发钱」。一期不对接银行转账。
- 员工查阅：未读 / 已读，可记录「有疑问」反馈。查阅不代表认可金额或收到款项。

已登记付款的工资更正保留原付款流水，通过补发/退款记录调整，不覆盖历史支付事实。本人年度工资汇总仅统计本人可见已发布数据。

## 7. 考勤台账与统计

月度台账按员工展示：应出勤小时、各类请假小时、外勤小时、申请/确认加班小时、调休变化、人工确认实到及异常、确认状态。没有实到依据时显示「待确认」，不能用「应出勤−请假」直接生成实际出勤或旷工；外勤和正常实到存在包含关系，不重复相加。

考勤和工资归属月份按用户确认采用北京时间自然月；与物流业务现有财务月份分开。统计仅纳入有效审批和已确认实际数据，并将未确认项单列。

| 报表 | 主要指标 | 范围 |
| --- | --- | --- |
| 考勤月报 | 应出勤、确认实到、假种时数、外勤、加班分类、待确认人数 | 本人 / 经理负责人员 / 行政与总经理全公司 |
| 工资月报 | 应发、扣款、实发应付、已支付、未支付、发薪人数、发布日期及支付日期 | 财务、总经理 |
| 考勤年报 | 各月及全年请假、外勤、确认加班、年假与调休使用 | 同考勤月报 |
| 薪资年报 | 各月及全年工资、补贴、公司承担、已支付与未支付 | 财务、总经理；员工看本人已发布汇总 |

工资成本按工资归属月汇总，现金支付按实际支付日汇总，两种口径明确区分；草稿不进入正式薪资统计。支持按月份/年度、部门、人员筛选和按权限导出。

行政完成月结后锁定当月考勤，财务据此核薪。未完成事项需处理或注明原因；补录、撤销、日历变更涉及已结月份时走有原因的更正，重新确认并通知财务，不自动改写已发布工资。部门调动后的历史报表按业务发生时保存的部门统计。

## 8. 最小落地设计与验收

建议复用现有 Vue、Express、MongoDB 和账号系统，不引入独立人事平台或通用审批引擎。固定两级审批即可满足目前需求。

核心数据：员工组织资料、公司考勤设置/日历、统一申请单（含审批轨迹）、假期余额流水、月度考勤记录、工资条版本、工资支付流水。所有数据保留公司 ID、员工 ID 和必要历史快照；独立部署同样沿用现有租户上下文。

建议开发顺序：开关与员工关系 → 日历及三类申请/审批 → 月度确认和假期台账 → 工资录入、发布与保密 → 发薪记录与统计。

后续实现必须验证：

1. 军铁开启可见，其他公司关闭不可见；独立部署开关生效，关闭时直接调用接口也被拒绝。
2. 跨节假日、午休、补班、跨月时长准确；24小时与25小时走不同审批路径（按8小时制示例）。
3. 审批人缺失、自审、重叠申请、重复审批、撤销及余额返还均有明确处理。
4. 普通员工、经理、行政、系统管理员、平台运维均不能越权查看、导出或汇总他人工资；敏感授权和重置密码不能成为提权入口。
5. 未确认考勤不被统计为实到或旷工；月结更正不静默改变工资。
6. 草稿员工不可见，发布后仅本人及财务/总经理可见；已读不等于付款；跨月发薪、部分付款和修订不会重复统计。

## 9. 待确认的制度参数

本稿不因这些未决项阻止需求整理，开发前再确定：

- 一期是否需要打卡；若不做，采用行政确认月度实际考勤。
- 每周工作安排、每天工作时段、午休、一天折算小时数；「超过3天」是否采用工作时长口径。
- 总经理、薪资负责人、行政及直属上级的实际人员；总经理本人申请的指定审批人。
- 年假额度、调休折算和有效期、证明材料要求，以及长期假是否需要不同计时规则。
- 截图两列工资合计的确切公式、病事假/旷工列的单位，以及工资归属周期。
